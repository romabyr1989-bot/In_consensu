# Формат файла импорта согласий

Описывает вход эндпоинта `POST /api/v1/import/consents` (FR-4.5). Импорт нужен, чтобы перенести в In consensu
согласия, полученные до его внедрения: из договоров, анкет и исторической базы клиентов.

Импортированные согласия получают способ подписания `IMPORTED_LEGACY`, поэтому для каждой строки нужно
основание — ссылка на скан (`document_ref`) либо текстовое примечание (`note`).

## Как запустить

```bash
curl -X POST http://localhost:8080/api/v1/import/consents \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@clients.csv" \
  -F "source=CLIENT_BASE_IMPORT" \
  -F "dryRun=true"
```

Ответ — задача импорта. Прогресс и итог: `GET /api/v1/import/jobs/{id}`, построчные ошибки:
`GET /api/v1/import/jobs/{id}/report`.

**`dryRun=true` по умолчанию.** Пробный запуск проходит ровно тот же путь проверок, что и боевой, и ничего
не сохраняет. Сначала прогоняйте файл в пробном режиме, разбирайте отчёт и только потом запускайте с
`dryRun=false`.

## Колонки

Порядок колонок произвольный, регистр заголовка не важен. Разделитель — запятая или точка с запятой
(определяется по заголовку). Кодировка — UTF-8, BOM допускается.

| Колонка | Обяз. | Описание |
|---|---|---|
| `external_id` | да | Идентификатор клиента в мастер-системе. По нему субъект создаётся или обновляется |
| `last_name` | да | Фамилия |
| `first_name` | да | Имя |
| `middle_name` | нет | Отчество |
| `phone` | нет | Телефон в любом виде: `+7 916 000-00-41`, `8 (916) 000-00-41`, `79160000041` |
| `email` | нет | Адрес электронной почты |
| `consent_type_code` | да | Код типа согласия из справочника, например `PDN_PROCESSING` |
| `form_code` | нет | Код формы, по которой было получено согласие |
| `form_version` | нет | Номер версии формы. Без него берётся опубликованная версия |
| `granted_at` | да | Дата или момент выражения согласия |
| `valid_until` | нет | Срок действия. Пусто — согласие бессрочное или действует до отзыва |
| `source` | да | Источник согласия, значение перечисления `ConsentSource` |
| `source_ref` | нет | Ссылка на документ: номер договора, номер обращения |
| `third_party_inn` | нет | ИНН третьего лица. Обязателен для типов, требующих третье лицо |
| `pdn_categories` | нет | Категории ПДн через `,`, `;` или `|`. Пусто — берутся из пункта формы |
| `document_ref` | нет* | Ссылка на скан документа в хранилище |
| `note` | нет* | Текстовое основание, если скана нет |

\* Нужно заполнить `document_ref` или `note`: без основания импортированное согласие недоказуемо (FR-4.2).

### Форматы даты

Принимаются три записи, любая из них — в колонках `granted_at` и `valid_until`:

- `2025-03-12T09:41:00+03:00` — момент с указанием зоны;
- `2025-03-12` — дата ISO;
- `12.03.2025` — дата в привычном виде.

Дата без времени трактуется как начало дня в таймзоне оператора (по умолчанию `Europe/Moscow`), иначе
согласие «сдвинулось» бы на сутки.

## Пример JSON

Файл, начинающийся с `[`, разбирается как JSON-массив объектов с теми же именами полей:

```json
[
  {
    "external_id": "CRM-1002346",
    "last_name": "Чкалов",
    "first_name": "Пётр",
    "consent_type_code": "PDN_PROCESSING",
    "granted_at": "2019-09-01",
    "source": "CLIENT_BASE_IMPORT",
    "source_ref": "БАЗА-2019",
    "note": "перенос из базы клиентов"
  }
]
```

## Повторный запуск

Строка опознаётся по четвёрке `source` + `source_ref` + `consent_type_code` + `external_id`. Повторная
загрузка того же файла не создаёт дублей: уже импортированные строки засчитываются как импортированные,
а не отклоняются.

## Отчёт об ошибках

Ошибочная строка не останавливает файл: каждая строка обрабатывается отдельно, а её ошибки попадают в отчёт.

```json
[
  {"line": 5, "field": "granted_at", "message": "Дата должна быть в формате ISO-8601, гггг-мм-дд или дд.мм.гггг"},
  {"line": 9, "field": "row", "message": "Тип согласия не найден: НЕТ_ТАКОГО_ТИПА"}
]
```

`line` — номер строки в файле с учётом заголовка. В отчёт попадают первые 1000 ошибок; полное число
отклонённых строк всегда видно в поле `rejected` задачи.

## Ограничения

- Размер файла ограничен настройкой `INCONSENSU_IMPORT_MAX_FILE_SIZE` (по умолчанию 64 МБ).
- Согласие регистрируется по опубликованной версии формы. Для `source=CLIENT_BASE_IMPORT` допускается
  ссылка на архивную версию, если дата согласия попадает в период её действия (FR-2.3).
- Неактивный тип согласия строку отклоняет: старые согласия такого типа продолжают действовать, но новые
  записи по нему не создаются (FR-1.1).
